#linux #methodology

Sequential checklist for CTF-style Linux boxes: you already have some form of access (reverse shell, low-priv creds, whatever) and the goal is user.txt → root.txt. Work top to bottom. Each phase links to the note with the actual detail — this page is the *order*, not the *how*.

A link that shows up red/unresolved is a technique you haven't written up yet. Don't skip it — go learn it on the box, then come back and fill the note in. That's how this list gets sharper over time.

## Phase 0 — Orient
- [ ] `id` / `whoami` — who am I
- [ ] `hostname`, `uname -a`, `uname -r', `cat /etc/os-release` — what am I on (kernel + distro version matters later for [[Kernel Exploits]])
- [ ] `pwd`, `ls -la ~` — where did I land
- [ ] Check if its a raw shell:
	- [ ] - Press **Tab** — nothing autocompletes
	- [ ] Press an **arrow key** — you get garbage like `^[[A` printed instead of recalling a previous command]
	- [ ] Hit **Ctrl+C** to kill a running command — it kills your _entire shell_ instead
	- [ ] Run `su`, `passwd`, `vim`, or `top` — they hang, misbehave, or error with something like `must be run from a terminal` / `TERM environment variable not set`
	- [ ] Run `tty` — it says `not a tty`
- [ ] If it's a raw reverse shell, stabilize it first:
  ```bash
  python3 -c 'import pty; pty.spawn("/bin/bash")'
  # Ctrl+Z
  stty raw -echo; fg
  export TERM=xterm
  ```

## Phase 1 — Grab the easy flag
- [ ] `find / -iname user.txt 2>/dev/null` (almost always in the current user's home dir)
	- [ ] or from home: `grep -rn <flag-format>`
- [ ] Note it and move on — root is the actual goal

## Phase 2 — Know your access before you enumerate anything else
- [ ] `sudo -l` — can I already run something as root? Check the output against GTFOBins immediately → [[11.4 SUID + GTFO Bins]]
- [ ] `id` / `groups` — am I in `docker`, `lxd`, `disk`, or `adm`? Each is a privesc path by itself → [[Docker Group Privesc]]
- [ ] `cat /etc/passwd` — who else exists, who has a real shell → [[11.2 Important Paths]]

## Phase 3 — File system sweep
- [ ] SUID/SGID binaries → [[11.4 SUID + GTFO Bins]]
- [ ] Capabilities: `getcap -r / 2>/dev/null` → [[Capabilities]]
- [ ] World-writable files/dirs: `find / -writable -type d 2>/dev/null`
- [ ] Sensitive paths — shadow, sudoers, ssh keys, bash_history → [[11.2 Important Paths]]
- [ ] Check exes owned by root: `sudo find / -type f -user root -executable`
## Phase 4 — Process & network sweep
- [ ] What's running as root, what's listening internally → [[11.3 Processes and Ports]]
- [ ] `pspy` if you can drop a binary, to catch cron/scheduled jobs firing in real time → [[Cron Jobs]]

## Phase 5 — Scheduled tasks & PATH abuse
- [ ] `cat /etc/crontab`, `ls /etc/cron.*`, `crontab -l` → [[Cron Jobs]]
- [ ] Does a cron job or SUID script call a binary without a full path? → [[PATH Hijacking]]

## Phase 6 — Credential hunting
- [ ] `.bash_history`, app/service config files, `.ssh/` → [[11.2 Important Paths]]
- [ ] `grep -ri password /etc /var/www /opt -R 2>/dev/null`
- [ ] Environment variables leaking creds: `cat /proc/[pid]/environ | tr '\0' '\n'` → [[11.2 Important Paths]]

## Phase 7 — Automated sweep (sanity check, not a shortcut)
- [ ] Run `linpeas` / `LinEnum` *after* your manual pass to learn what it's finding, not just paste output
- [ ] Cross-check anything it flags against the relevant note above before acting on it

## Phase 8 — Escalation vectors still undocumented
Work through these once you've exhausted the above:
- [ ] [[Sudo Misconfiguration]] — beyond the simple GTFOBins case: version CVEs, `env_keep`, `LD_PRELOAD`
- [ ] [[Kernel Exploits]]
- [ ] [[Writable Services]] — systemd units or init scripts you can edit/replace
- [ ] [[NFS no_root_squash]]
- [ ] [[Docker Group Privesc]] / LXD breakout
- [ ] [[Wildcard Injection]]

## Phase 9 — Root, then log it
- [ ] Get root.txt
